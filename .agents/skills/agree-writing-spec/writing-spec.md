# Writing specification format

Create the paper's `SPEC.md` only for an actual writing task. This template describes the fields; it does not supply agreed mathematical claims. Keep author notes and expected exposition answers out of checker assignments.

## Scope and agreement

Record the target paper and source entry point, the precise task, exclusions, baseline version, agreement status and the user's actual scope decision. Distinguish a proposed specification from an agreed one. List unresolved material questions explicitly.

## Claims and prerequisites

Record each target claim, algorithm variant, assumptions, quantifiers, conclusion strength and relevant definitions/citations. Identify claims that are already in the draft versus proposed changes. State reader prerequisites and what the manuscript is expected to teach or supply through a stated supporting result.

## Increments and dependency contracts

For each unit, record its stable ID and manuscript label, intended result, inputs/assumptions, exact conclusions available to dependents, proof location, and verification state of dependencies. Distinguish logical dependencies, references to shared setting and expository ordering. Record the proposed order and which branches can actually be reviewed independently.

Specify the first unit and completion criteria: current correctness, notation and independent exposition evidence, with no open blocking findings. Record any global notation changes being proposed and their scope.

## Author notes

Keep possible proof mechanisms and alternatives here only if useful to the writer. Do not treat them as part of an approved proof. Prepare the exposition assessment for each reviewed version in its author-only session section, before seeing reader responses. Neutral checker briefs contain only selected claims, prerequisites, scope, version and mathematical dependencies.
